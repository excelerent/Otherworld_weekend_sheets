# Project Goal: Party Tracker Sheet Creator (Google Sheets)

Our goal is to create a tool to be used by staff members during the event to enter information about the party and their progress throughout the weekend. This tool will generate a Google Sheet using Google Apps Script.

## Inputs
We will take in information from the following JSON files (generated by other exporters):
* `PartyPaths.json`: Contains the encounters for each party.
* `ChargeTable.json`: Contains the charge information for each party.
* `Parties.json`: Contains general information about each party (Companion, Staff Member, Background Color, Table Color, Text Color).

## Output
A Google Sheet created via Google Apps Script. The script will be written in TypeScript and converted to Apps Script using `clasp`.
When rebuilding the sheets, all existing named ranges with prefixes `Combat_`, `Path_`, and `Charge_` should be removed before being recreated.

## Sheet Structure

### Combat Sheet
* The first sheet is the **Combat** sheet.
* It lists monster groups and parties in a grid of checkboxes.
  * Cell A1 should be empty
* The header row (containing the party names) should be colored according to the each party.
  * Both BackgroundColor and TextColor should be drawn from the corresponding party in `Parties.json`.
* Each monster type row should be colored according to the following:
  * Chitter - #d0e0e3
  * Skeever - #fce5cd
  * Worlog - #e6b8af
  * Wolven - #efefef
  * Creeper - #d9ead3
* Rows should alternate between light and dark versions of the colors above
* Monster name column should be centered, and 110px wide, 25px high.
* Each checkbox cell should be 60px wide.
* After all the party columns, add a notes column (width 600px), which should be colored as well (based on the color of the monster row).
* Create a **Named Range** for each party column in the Combat sheet, named `Combat_{PartyName}` (e.g., `Combat_Arden`).
* **Note:** This sheet should be left alone for now (e.g., copied from a template or left as a placeholder).

### Party Sheets
Every other sheet is a **Party sheet**, named and colored according to the party.

#### Header Section
* Create a heading row (Row 1) which should be frozen, and NOT merged.
* It contains the **Party Name** in Cell A:1, which should be capitalized.
* It contains the **Companion Name** ({staff member playing that companion}) in cell C:1.
* The entire title row should be colored to the party (BackgroundColor and TextColor).
* The entire title row should be bold and 27 pt font.
* Information is sourced from `Parties.json`.
* Column widths
  * A: 200px
  * B: 90px
  * C: 600px
  * D: 20px
  * E: 20px
  * F: 120px
  * G: 150px
  * H: 250px

#### Character Info Section (Top Right, F3 - H9)
* The Header should start at F:3 and be 10pt bold.
* Starting at cell **F:4**, create a section for Character names/descriptions for each of the participants in the party, for each role:
    * Caster
    * Keeper
    * Maker
    * Ranger
    * Seeker
    * Traveler
* Column F should have no label
* Column G should be labeled Name
* Column H should be labeled Description
* Each character in F should be colored according to the party (TableColor and TextColor).
* cells should alternate between white and light gray and have a no internal boarder
* The entire table, save for the title row should be surrounded by a border


#### Party Path Table
* Starts at Row **A:4**.
* The title row should be bold, 14pt, and formatted as "PARTY PATH"
* The header row is colored according to the party (TableColor and TextColor).
* The header row should be bold and surrounded with a border.

    1. **Character** (text) - The `CharacterName` from `ChargeTable.json`.
    2. **Gave Info** (checkbox).
    3. **Notes** (text) - should be empty.

* When the "Gave Info" checkbox is checked, the text in the "Character" column should be greyed out (font color `#999999`).


#### General Notes Section

### Export Routine (EM Dashboard Sync)
To minimize latency and avoid slow `IMPORTRANGE` calls, the Party Tracker will push data to the **EM Dashboard** (a separate spreadsheet) automatically when changes occur.

#### Export Sheet
* A hidden sheet named **"Export"** will be created in the Party Tracker.
* This sheet serves as a centralized buffer for data being pushed to the EM Dashboard.

#### Dashboard Sheets
The EM Dashboard spreadsheet contains the following sheets that receive data (cell content only):
* **{PartyName}_Import**: A value-only echo of the corresponding Party sheet in the Tracker.
* **Combat_Import**: A value-only echo of the Combat sheet in the Tracker.

#### Implementation Details
* An `onEdit` trigger will be implemented in the Apps Script.
* **Important:** To avoid permission issues and ensure the script runs with full authorization, we use an **Installable Trigger** tied to a function named `handleOnEdit` (renamed from `onEdit` to prevent the "Simple Trigger" from firing automatically).
* A `setupInstallableTrigger()` function is provided in the script to automate this process. Run it once from the **Party Tracker Debug** menu in the spreadsheet.
* A `syncAllToDashboard()` function is also available in the **Party Tracker Debug** menu to force-sync all sheets (Combat and all Party sheets) at once. This is useful for initial setup.
* **Note on Permissions:** If you encounter a permission error, re-run `setupInstallableTrigger`. This ensures the trigger is bound to the latest authorized scopes.
* When a change is detected in any Party sheet or the Combat sheet, the routine will push the updated values to the corresponding sheet in the EM Dashboard spreadsheet.
* The script is configured with the Spreadsheet ID of the EM Dashboard.
* **Performance Note:** The sync uses `clearContents()` and `setValues()` to minimize latency when pushing data across spreadsheets.

* make sure you clasp push the script to the sheet when you have made your changes
